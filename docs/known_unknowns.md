experiment that would answer it. Close an entry by linking the task or
experiment that answered it.

| ~~Is this image a verified Redump dump, and what does "(2M)" distinguish?~~ | Answered: equal to Redump 58190; "(2M)"/"(1M)" mark two masterings with the same track 01 (`references/saturn_jp/README.md`). | — | `ENV-007` |
| ~~Which cartridge setting does the game need?~~ Partly answered: none for boot and attract (D-003). Still open: does play (Start, story, fights) check or use the cart, and what does the header's `W` mean? | `none` and `backup` give the same boot and attract screens with ~1 s timing shifts; 1 MiB and 4 MiB identical (`EXP-0002`). Wikipedia says the Saturn version requires the 1 MB cart (citing *Sega Saturn Magazine*), matching Mednafen's database. | One play session start (Start, mode select, first fight) with `ss.cart none`, compared with `auto`. | later `EMU` task, if it ever matters |
| Is the story dialogue drawn from the plain Shift-JIS strings in `END.BIN`, `VICTORY.BIN` and `STG0AS.BIN`? | One byte-identical table of 1,851 lines in all three, every line pointed to at base `0x06060000` (D-008, static). Not yet seen in RAM. | Shift-JIS search of WRAM at a checkpoint with a known line on screen; then a one-character RAM change. | `TXT-001`, `DBG-004`, `RE-001` |
| Which of the three script copies does the game read, and when? | The three tables are byte-identical and all three files point at `0x06060000`, so they probably replace each other as overlays (D-008). | Write breakpoint on the RAM text from a pre-load checkpoint, in a stage, after a win, and in an ending. | `DISC-001` |
| Is `KANJI.BIN` the dialogue font, and what is its format? | The box glyphs are anti-aliased 4 bpp cells (values 0, 9-14), copied from a WRAM-H shadow; `KANJI.BIN`'s nibbles have the same palette, but the glyph is not found in 16×16 1-bit or 4 bpp row layouts (EXP-0016). | Write breakpoint on the WRAM-H shadow cell `0x060FE200` while the box types; follow the reader back to its source. | `FONT-001` |
| ~~Where and how does the arcade store its English dialogue?~~ | Answered (D-009, D-010): table, map, on-screen use, slot variable, region choice, the four codes. Still open: whether endings come from it (candidate reader `0x97222`), and what `$15`/`$19` of the script task and `$AD(A5)` mean. | Reach one ending in MAME (vitality forcing, as the siblings did) with read taps. | `END-001` |
| Does the Saturn renderer keep any arcade English or half-width path? | Dialogue lines already contain half-width ASCII (`!`, `?`, space, a few letters; D-008), so the renderer may draw single-byte characters. Such a leftover saved XvSF all font capacity work. |
| Do all scenes share slot numbers across the arcade's languages, as the first scene does? | Same draw code and script for every region; `cybotsj` and `cybotsu` show slots 0-5 in the first scene (D-011). | Compare slot sequences for a second scene in both sets (e.g. after the first fight, by vitality forcing). | before `GATE-TRANSLATION` |
| What are lines 899-1850 of the Saturn script? | No arcade counterpart; Chiyomaru and Tessan appear only there (D-011). | Play or force one console-only pilot's story and match its lines. | `SPECIAL-001` |
| Is Latin name art on the Saturn disc, and where is the name-sprite table? | The VS name art is raw VDP1 sprite data in `SELECT.VAD` (`0x1EE80`, `0x1F0A0`); its neighbours do not read as a name list (EXP-0012). | Break on the VDP1 command write for the name sprite at the VS screen; read the source address it copies from and the table that indexes it. | `LOC-001` |
| Are any names spoken? | Not checked. | Listen to the VS screen and story scenes of one session with sound. | `LOC-001` |
| What are the records that point at the dialogue lines? | 4-byte-aligned pointers after the table, gaps of 8/16/24/32 bytes, targets in file order; a sample: small numbers, a line pointer, `FFFF 0000`, another line pointer (D-008). | Disassemble the code that reads one record while a line draws (agent breakpoint on the record). | `RE-002` | Disassemble the text routine around region/language reads once `FONT-001` finds it. | `FONT-002` |
| What do audio tracks 42-62 (the per-pilot `*_END*` entries) hold: ending music or voiced narration? | Layout answered (D-002): one ISO entry per audio track; the 21 `*_END*` entries are tracks 42-62, two or three per pilot. Content not checked. Wikipedia says the console ports voice the story mode ("citation needed"). | Listen to one track, or reach one ending and note which track plays. | `END-001` |
| Is cart RAM extraction valid, and how should the extractor read a 1 MiB cart? | State section `CART_EXTRAM` holds `LO`/`HI`, 512 KiB each; `mcs_extract`'s entry expects 4 MiB and refuses (`EXP-0005`). The stock debugger has no cart space to compare with. | Size the entry from the state, then compare a cart word read by the agent interface with the extracted copy. | only if cart RAM ever matters |
| Why do some unattended debugger runs lose keys or dumps silently? | `EXP-0003` run 1 lost an F9; `EXP-0004` run A lost both WRAM-L dumps; `EXP-0005` run G never opened the memory editor.
